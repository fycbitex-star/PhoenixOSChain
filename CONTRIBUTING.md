# Contributing

## Contribution Standard

Contributions should strengthen clarity, correctness, security, or operational maturity.

Do not submit hype-driven edits, fake performance claims, fake decentralization claims, or placeholder production claims.

## Expected Workflow

1. keep changes scoped
2. preserve truth-first language
3. document architecture and operational consequences
4. include validation steps with code changes

## Before Opening a PR

- run `go test ./...`
- update affected docs
- describe risks introduced or reduced
- avoid committing secrets, validator keys, or runtime state

# Governance and Treasury

PhoenixChain treats governance and treasury as infrastructure concerns, not community theater.

## Governance Direction

The intended governance stack includes:

- proposal lifecycle
- validator-aware participation
- voting identity
- quorum and threshold enforcement
- execution queue
- timelock posture
- public audit trail

## Treasury Direction

Treasury surfaces are designed around:

- allocation intent
- recipient validation
- execution delay
- emergency blocking posture
- auditable state changes

## Truth-First Rule

This repository does not claim that treasury balances, decentralized voting power, or mainnet-safe governance execution are already complete where they are not.

That honesty is part of the system design.

# Architecture Overview

PhoenixChain is currently organized around several institutional concerns:

## Chain Core

- block validation
- genesis management
- transaction verification
- account state transitions

## Validator Runtime

- fixed validator devnet operations
- health surfaces
- operational documentation
- transition path toward broader validator participation

## Governance Runtime

- proposal lifecycle foundations
- voting records and audit trail foundations
- treasury safety posture
- execution-queue and timelock direction
- governance impact receipts for consequence and blast-radius visibility

## Asset Layer

- native PHX monetary architecture
- canonical native-asset-first contract strategy
- PHX-20 token runtime
- explorer and wallet visibility

## Public Surfaces

- explorer
- governance explorer
- validator pages
- staking portal posture
- treasury and audit surfaces

## Operating Reality

Some surfaces are already runtime-backed.
Some are still conservative blocked states rather than fake finished systems.

That is deliberate.
